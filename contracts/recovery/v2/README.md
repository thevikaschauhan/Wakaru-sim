# Recovery v2 contracts (AF01)

Engine is canonical. Distribute this directory byte-for-byte to Inkwell, Wakaru and Web; verify manifest hashes in each checkout. Version changes require explicit migration, never reinterpret intelligence/v1 or buyer_state_v1. This slice does not enable follow-ups or TypeSafe inference.

Run `python3 -m pip install -r requirements.txt` in an isolated environment, then `python3 verify.py`. The verifier validates schemas, primitive shapes, distribution sums (1e-6 tolerance), Score weighted values, complete bundles, bindings, evidence membership and fixture expectations. `verify_pair` binds responses to exact requests. Runtime consumers must enforce these rules before accepting model results in AF06/AF07; schemas alone cannot prove evidence completeness or factual truth. Model output never authorizes dispatch.

Semantic input/request hashes: UTF-8 JSON, ASCII object keys sorted recursively, no whitespace, unescaped Unicode, arrays preserved, integers only for JSON numeric input values. Encode fractional observed quantities as decimal strings, money as integer minor units. No NaN, duplicate keys or unknown fields. Floats are permitted in result probabilities, not request identities. Provider raw payload hashes are a separate domain: Engine hashes JSON compacted with Go encoding/json UseNumber and sorted keys; replay compares exact canonical payload bytes, never occurrence seconds.

Journey identity is merchant/store/origin episode plus verified recipient alias, with immutable original abandonment and expiry. AF03 will enforce ownership and lifecycle transitions in the database. Signal IDs and provider IDs are separate. Same source/account/event ID with a different payload hash is an integrity conflict; consumers retain both diagnostics and never overwrite the original. A fallback digest is marked weaker and cannot distinguish byte-identical provider events lacking IDs.

TF01-TF08 are application tasks, not native provider endpoints. TF03 is Score 0-3; TF06 Noul has a yes-probability and no confidence property. Missing/invalid/stale answers require review, never zero risk. TF08 is contract-only and disabled. The policy defaults are rehearsal constraints, not proven conversion optimization. Complete draft coverage and every applicable mandatory check are required; one failed safety check cannot be averaged away. Source facts and provider/model allowlists remain application checks.
